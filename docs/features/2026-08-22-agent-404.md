# Feature: Markdown guidance block on the 404 page

**Branch:** feat/agent-404
**Date:** 2026-08-22

## Summary
`404.html` now carries a short plain-Markdown block ("# 404 … ## Where to look next …") next to
its HTML pointers, so clients that asked for `text/markdown` and readers that strip HTML still
get the sitemap, llms.txt and home links as Markdown.

## Motivation
The Is Agentic audit (is-agentic.com, scans run by Ora) scored "Agent-friendly 404s" at 50%
after the 2026-08-22 work: the status code is a real 404, but "for full credit, include a short
markdown body (site map links, where to look next) so agents can recover". GitHub Pages serves
`404.html` as `text/html` only, so the Markdown lives inside the page as a `<pre class="md">`
block. The same block ships in each project site's `docs/404.html` for parity.

## What changed
- `404.html`: new "For agents" section with a `<pre class="md">` block — H1 `# 404: no page at
  this path on tatendaz.github.io`, `## Where to look next`, and a list with `[Site map]`,
  `[llms.txt]`, `[Home]` · `[About]` · `[Contact]` links (absolute URLs).
- `assets/site.css`: `.page pre.md` style (monospace, wrapped, bordered, theme-aware).
- `tests/test_site.py`: `test_markdown_pointer_block_for_agents` — block exists inside
  `<main>`, starts with `# 404`, has the heading and the three links, stays under 600 chars, and
  contains no HTML.
- `tests/test_live.py`: the live 404 body must contain the Markdown lines.

## Notes
- The 404 body stays under the 1,500-character limit enforced by the existing test.
- Score ceiling: ora.ai/methodology gives 2/2 only when the `Accept: text/markdown` probe gets a
  real 404 **served as `text/markdown`**; an HTML 404 with a Markdown block inside `<pre>` still
  scores 1/2 (two sites with exactly this pattern were scanned on 2026-08-22 and got 1/2). GitHub
  Pages serves `404.html` as `text/html` only, so this change helps agents but does not raise the
  score. Full credit needs a negotiating layer in front of Pages (for example a Cloudflare Worker
  on a custom domain that answers 404s with `text/markdown` + `Vary: Accept` when Markdown is
  preferred) — a hosting decision, the same one that blocks the "Markdown content negotiation" check.
